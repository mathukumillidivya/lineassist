What these results do not show

  • New combinations, not new problems. The test calls mix the same kinds of fault as the development calls, in different sets, on the same customer account.
  • The customer is simulated. It always has its phone, always cooperates in the end, and never misreads a screen.
  • Not comparable to the public leaderboard. Both agents talked to a lower-cost customer simulator than published results use. Only the comparison between the two agents holds.
  • One model. Every call used Claude Haiku 4.5. A stronger model would start from a higher baseline.
  • The four layers are not separated. They were added one after another and never removed one at a time, so the share each contributes is not isolated.
HOW IT'S BUILT

One turn of a call

Before anything was built, the standard agent's development calls were read to find out why it failed. Each layer answers one of those failures. Two are ordinary code, so they behave the same way every time.

INPUT

Customer speaks, or a lookup returns

The agent receives a message, or the result of an account lookup it asked for.

CODE

Case notes

Is this the customer's line, has the contract ended, is the data allowance used up: worked out and attached.

PROMPT

Playbook

The model drafts its next move from the provider's manual, reorganised into one ordered checklist per problem.

CODE

Line check

If the draft acts on a line whose number is not the customer's, it is withheld and the agent is told which lines are left.

SECOND MODEL CALL

Hand-off guard

If the draft passes the customer to a human, a reviewer lists checks not yet done. Any left, and the transfer is withheld. Transfers the policy requires are allowed, and after three overrules the agent's choice stands.

Development, in the order it happened

Calls solved out of 74 development calls, one attempt each. These are the calls the agent was designed against, so they flatter it and each step is noisy.

    Engineering notes

    • Frozen before testing. The agent was fixed at commit aac2c62 before the test split was run, and the test split was run once.
    • Resampled by task. The 51-point difference has a 95% interval of 33 to 68, resampling tasks rather than conversations.
    • Live demo, same layers. The benchmark's phone and account simulator runs in the browser through Pyodide. One server function holds the key, fixes the prompt and tools, and caps use per visitor and per day.
    • The hand-off guard added one call in development, within run-to-run noise. Its value is not established.
