How the 120 calls ended

The standard agent's main failure is giving up: it fixes one or two faults, sees the problem is still there, and hands the customer to a human while the fix was still available.

The call it gets wrong

All three LineAssist failures are the same call, and it is a rule violation.

The line was suspended because its contract had ended, which the provider's policy says an agent must not lift. LineAssist took payment for an overdue bill and reactivated the line anyway. The fix is to enforce that rule in code, the way the line check already works. It has not been applied, because changing the agent after seeing the test calls would make the result above dishonest.

What this does not show

  • Unseen means new combinations, not new problems. The test calls combine the same kinds of fault as the development calls, in different sets, on the same customer account.
  • The customer is simulated. It always has its phone, always cooperates in the end, and never misreads a screen. Real callers do none of these reliably.
  • Not comparable to the public leaderboard. Both agents talked to a lower-cost customer simulator than published results use. Only the comparison between the two agents holds.
  • One model. Every call used Claude Haiku 4.5. A stronger model would start from a higher baseline.
  • The layers are not separated. They were added one after another in development and not removed one at a time, so the share each contributes is not isolated.
Benchmark: tau-bench (tau2-bench), Sierra Research. Built by Divya Sri.

What was built

Four layers around an unchanged model

The failures of the standard agent were read from recorded development calls before anything was built. Each layer answers one of them. Two are plain code, so they behave the same way every time.

Prompt

Playbook

The provider's own manual, reorganised into one ordered checklist per problem, with a rule to keep going until the phone passes its check. The agent asks for one named action at a time and never describes screens it cannot see.

Code

Line check

An account can hold several lines. Any action that names a line is withheld unless that line's number is the number the customer gave. The standard agent changed settings on someone else's line.

Code

Case notes

Facts that follow mechanically from account data are computed, not left to the model: is this the customer's line, has the contract ended, is the data allowance used up.

Model call

Hand-off guard

Before a customer is passed to a human, a second review lists checklist items not yet examined. If any remain, the transfer is withheld. It can overrule the agent three times at most.

Where the gain came from in development

74 development calls, one attempt each, layers added in this order. These are single runs on the calls the agent was designed against, so they overstate performance and each step is noisy. The hand-off guard added one call, which is within noise.

What the standard agent got wrong on those calls

  • Gave up early. 40 of its 52 failures were hand-offs to a human while a fix was still available.
  • Worked on the wrong line. In 39 of 52 failures it never looked at the customer's own line. In 26 it read or changed another one.
  • Skipped the data allowance. It missed the data top-up in 34 of the 38 calls that needed one.
  • Invented menus. It described buttons it could not see, and the customer then reported doing things that never happened on the phone.
